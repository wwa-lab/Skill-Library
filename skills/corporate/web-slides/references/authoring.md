# 内容、品牌与输入约定

## 内容准备

输入可以是主题、原始材料、Markdown 或 PPTX，最终都归一到 `model-contract.md` 的 v1 JSON。JSON 是持久内容模型：不直接拼写幻灯片 DOM，避免网页和导出内容分叉。

- 主题：用获准 Agent/模型确定听众、主要问题与页序；无法核实的数据不用看似真实的数字填充。默认现场讲述，细节写在讲稿。
- 文档：读取用户已授权材料。PDF/Word 的提取不由这个 Skill 假装全自动；使用环境已有的获准工具，不安装新依赖。核对段落、表格、图片与来源，再生成模型。如果无法读取格式，明确说明并使用用户提供的文本版本。
- Markdown：轻量解析支持每页 `#` / `##` 标题、普通文字、项目符号、独占分隔线 `---`、每页一张本地 `![说明](路径)` 图片、`<!-- notes: 多行讲稿 -->`。不解析 Markdown 表格、代码围栏、链接或原始 HTML；会报错，请让 Agent转为 JSON。**这不是完整 Markdown 排版器。** 强调符号、编号等没有特殊样式时作为字面文本保留。
- PPTX：先用 `ooxml.py`，检查转换报告。POTX/PPTX 品牌分析只在本机进行。
- 已有本 Skill HTML：使用编辑器；Agent 如需批量修改，读取 `#deck-data` 的 JSON 后重构建。普通第三方 HTML 不作为可信可执行模板。

讲稿包括过渡语、补充解释和来源；不把展示页写成密密麻麻的文档。多段中文保持换行。图片标注用途和来源，实际用户材料不下载到第三方。

## 默认品牌

| 项目 | 默认 |
| --- | --- |
| 画布 | 1600×900 设计像素 / PPTX 13⅓×7.5 英寸 |
| 颜色 | 红 `C8102E`，白 `FFFFFF`，黑 `171717`，辅助灰 `666666` |
| 字体 | Microsoft YaHei；网页回退 PingFang SC / 系统 sans-serif |
| 标题 | 常规 58px（PPTX 34.8pt）；封面 82px（49.2pt），粗体 |
| 正文 | 32–40px（19.2–24pt）；数据标签 24–28px |
| 安全区 | 默认左右 100px，内容 y=255–800；页脚 y≈838 |
| 动画 | 短距离淡入，系统/手动减少动态生效；导出静态终态 |

整体等比缩放，投影为 4:3 时上下/左右留边，不打散版式。每页标题建议 ≤22 个汉字，硬上限 52 个字符；正文通常不超过 3–5 个短要点。输入字数上限仅防止异常数据，不是排版容量。超出框时优先改写或拆页；浏览器用橙色虚线提示并阻止导出溢出页。

品牌模板只提供规范，不应被当作公司事实来源。无真实 Logo 时不生成假 Logo。`brand.name`、颜色、字体和已确认 `logo` 驱动网页与 PPTX 通用母版。源模板 `masters` / `layouts` 是审查资料；本版仅重建 cover/content/data/imported 布局体系，复杂源母版不自动还原。

## 模型创作示例

从 `assets/deck-template.json` 复制，保留结构，将 id 设置为项目特有值（用于缓存隔离），再逐页替换标题、讲稿与对象。图片路径相对 JSON 所在目录解析，也可用本地绝对路径；构建结果会改为嵌入 data URL。禁止远程及网络共享图片路径。

风格探索生成三组真实预览，每组必须检查封面、内容页和数据页。选中候选后，将它的品牌及必要逐元素颜色调整应用到完整模型；不要只把候选名字写进最终文件。已有明确默认风格指令则直接生成，不再要求重复确认。

## 导出约定

所有网页对象进入 PPTX 时使用相同坐标比例。文字和图片独立；流程图的框、箭头、标签可分别编辑；表格是原生表格，图表带工作簿；讲稿作为 notesSlide 保留。图片 cover 按对象位置裁切成独立 PNG，原始图仍在 HTML 模型，PPTX 仅含裁切后图片。静态图表细节由 Office 自己排版。

复杂对象应先列明可保留与需替代的部分，用户同意栅格化时仅栅格化该对象，并在报告中记录对象位置与处理方式。本版没有自动截图/栅格化复杂对象功能。不能把整页图片包装成“可编辑 PPTX”。
